# 本評価：動画の選び方と正解ラベルの決め方

動画単位の炎上検知（見逃し・誤警戒・検知までの時間）を評価するための手順。
**正解ラベルと炎上開始時刻は、コメントを見る前に、コメントとは独立した資料だけで決める。**

---

## 1. なぜ「炎上より前に公開された動画」に限るのか

手法A・B・Cはいずれも、その動画の**直前24時間**の水準と比べて変化を検知する。最初の24時間は「履歴不足」で判定しない。
そのため、次の動画は本評価に使えない。

- 公開直後から批判が集中した動画（炎上が公開と同時に始まる。例：問題発言を含む動画そのもの、謝罪動画）
- 騒動が報じられた後に公開されたニュース動画（スシロー報道 Thc7JIJk6Co と同じ。事例紹介に回す）
- 削除・非公開になった動画（コメントを取得できない）

**使える動画**：炎上のきっかけ（不祥事の発表・報道など）の**24時間以上前**（できれば7日以上前）に公開され、きっかけの後もコメントを受け付けていた動画。
例：企業や当事者の公式チャンネルで以前から公開されていたCM・紹介動画、きっかけより前に公開された関連ニュース動画。

## 2. 正解ラベルの定義

| 列 | 決め方 |
|---|---|
| `is_fire` | 1：その動画のコメント欄で批判が集中したことを、**報道記事**が報じている（記事のURLを `label_source` に記録）。0：比較用（下記4節） |
| `fire_start_jst` | 炎上のきっかけとなった出来事が**最初に公になった時刻**。優先順位：①公的機関・企業の公式発表の時刻（プレスリリース・適時開示・記者会見）②最初の報道記事の掲載時刻。分単位で記録し、出典を `label_source` に書く |
| `incident_id` | 同じ騒動に関する動画は同じID（dev/test の分割に使う） |
| `label_source` | 根拠資料のURLと、そこに書かれた時刻 |

- 時刻が分単位で確認できない炎上動画は `fire_start_jst` を空欄にする（検知の有無は評価するが、遅れの評価から外れる）
- コメントの増え方を見て開始時刻を決めない（検知結果との循環になる）
- 決めたら `freeze-labels` でハッシュを記録し、以後変えない

## 3. 例：根拠資料で開始時刻が確定できる事例

**小林製薬 紅麹関連製品の健康被害**（incident_id 例：`KOBAYASHI_BENIKOJI`）
- 厚生労働省の資料「小林製薬の紅麹を含む健康食品に対する対応の経緯」に、2024年3月22日 17:00 プレスリリース、18:00 記者会見、3月26日 10:00 第3報（死亡事例）の記載がある
  https://www.mhlw.go.jp/content/12401000/001236933.pdf
- `fire_start_jst` の候補：2024-03-22T17:00:00+09:00（最初の公式発表）
- **未確認**：3月22日より24時間以上前に公開され、コメント欄が開いている動画（公式チャンネルの製品CMなど）があるか、そのコメント欄で批判が集中したと報じた記事があるか。動画IDは YouTube で検索して確認する

※ これは手順の例であり、正解ラベルとしてはまだ確定していない。

## 4. 比較用（非炎上）動画の選び方

誤警戒を測るため、炎上動画と同じくらいの本数を用意する。
- **同じチャンネルの別動画**で、同じ期間に炎上が報じられていないもの（チャンネルの視聴者層をそろえる）
- **否定的な話題だが炎上していない動画**（災害・事故報道など。能登半島地震の避難報道 QbtnS7Uc8OI は候補）
- **好意的な話題の動画**（YouTubeテーマソング WJzSBLCaKc8 は候補。ただし現在の50件は1スレッドの76秒間に集中しており判定対象外。全件の取得が必要）
- 比較用動画にも「評価する期間」を決める（例：炎上動画の `fire_start_jst` と同じ日時の前後72時間、または公開後の同じ長さ）。`is_fire=0`、`fire_start_jst` は空欄

## 5. 本数と評価の進め方（卒論の水準：2026-11-09 決定）

- **最低ライン**：炎上 5本以上・比較用 5本以上。信頼区間を付けた小規模評価として報告する（目標は各10本）
- **閾値は調整しない**：動画数が少なく dev/test に分けると各数本になるため、設計書の既定値に固定して全動画を1回だけ評価する（`fix-config`）。調整しないので、評価用の結果を見て閾値を変える問題は起きない
- **集計幅は3時間を主とする**：1時間集計では実データの大半が判定対象外になる（MVの9月9〜18日：1時間 6/240、3時間 23/80 時間帯で判定可能）。集計幅はコメント量（観測できる時間帯の数）だけを根拠に、本評価の前に決めた。1時間集計の結果も比較として併記する
- **採用前の確認**：各動画を `observe --freq 3h` にかけ、評価する期間（炎上動画は開始の前後、比較用は同じ長さの期間）に判定できる時間帯があることを確認してから採用する。判定できる時間帯が0の動画は採用しない（不採用の理由として記録する）
- 手順：`split --dev-fraction 0`（全動画を test）→ `freeze-labels` → `fix-config --freq 3h` → `test` → `report`。1時間集計の比較は、別の protocol フォルダで同じ手順を行う

（以前の目安「炎上 15〜20本・比較 15〜20本、dev 40%で調整」は、動画を十分に集められた場合の方法として残す）

## 6. 作業の流れ

1. 事件を選び、根拠資料で `fire_start_jst` と `label_source` を決める（コメントは見ない）
2. YouTube で、きっかけより24時間以上前に公開された動画を探し、`video_id` を記録する
3. コメントを全件取得する（返信も含める。`--max` は総コメント数より大きく）
   ```powershell
   .venv\Scripts\python.exe -m src.youtube_api https://www.youtube.com/watch?v=（動画ID） --max 30000 --replies
   ```
   表示される公開日時・取得率を `labels_candidates.csv` に記録する
4. `observe --freq 3h` で判定できる時間帯を確認し、採用する動画を決める
5. `labels.csv` に `comments_file` を書き、`split --dev-fraction 0` → `freeze-labels` → `fix-config --freq 3h` → `test` → `report`

**まとめて実行するスクリプト（2026-11-09 追加）**

```powershell
# 3. コメントの一括取得（キーは環境変数で渡す。スクリプトには書かない）
$env:YOUTUBE_API_KEY = "（手元のキー）"
powershell -ExecutionPolicy Bypass -File experiments\fetch_comments.ps1 -Ids qTnrEgRVEDk,KrkclH7G7S4

# 5. 本評価（採用条件の確認 → 3時間集計〔主〕→ 1時間集計〔比較〕）
powershell -ExecutionPolicy Bypass -File experiments\run_main_evaluation.ps1
```

`run_main_evaluation.ps1` は、炎上・比較が各5本未満、`comments_file` がない、炎上動画に `fire_start_jst` か `label_source` がない場合は、評価を始めずに止まる（test を無駄に消費しない）。1時間集計は `experiments\protocol_1h` と `results\eval_1h` に分けて記録する。

## 7. 予備評価との区別

フジテレビの会見前後の比較（TeRXuoLAX9o、基準時刻 2025-01-27 16:00 JST）は `event` コマンドで行う**予備評価**。
会見開始時刻は「会見から検知までの時間」を測る基準であり、`labels.csv` の `fire_start_jst` には入れない。

## 8. 候補の調査（2026-11-10）

### 8.1 基準時刻（fire_start_jst）の決め方
コメントを見ずに、次のどれかで決める（どれを使ったかを `label_source` に書く）。
1. 公式発表の時刻（自治体・企業のプレスリリースなど）
2. きっかけになった動画・投稿の公開時刻（YouTube の動画情報。`src.list_uploads` で取れる。削除・非公開の動画は取れないので報道で確認）
3. 騒動を最初に報じた記事の掲載時刻（SNSの拡散はそれより前に始まっていることが多いので、その旨を書く）

評価する動画は、基準時刻より24時間以上前に公開され、コメントが有効なもの。きっかけの動画そのものは、公開直後に履歴がないので対象にしない。
1つの騒動から複数の動画を選ぶ場合は同じ `incident_id` にする（本数は騒動の数でも数える）。

### 8.3 比較候補の選び方（騒動の影響が及びにくい動画）
- **A. 同じチャンネルの平常期**：炎上候補と同じチャンネルで、報道された騒動から前後1か月以上離れた時期に公開された動画。評価期間は公開後2〜11日目（公開直後の24時間は履歴不足のため除く）。チャンネルの規模やファン層がそろうので、比較として最も公平
- **B. 同じ時期・同じジャンルの別チャンネル**：同じ時期に公開された、同程度のコメント数の動画
- どちらも、ユーチュラのチャンネル別ニュース一覧（`https://yutura.net/channel/<番号>/news/`）や記事検索で、その期間に騒動の記事がないことを確認し、確認日と検索語を `label_source` に書く（「報道が見つからない」ことの記録）
- 同じ騒動の期間に同じチャンネルで公開された動画（例：マネーのクズ特別編 qTnrEgRVEDk）は比較に使わない
- こめおのチャンネルは騒動の報道が多く、平常期を選びにくい（A を使うならヒカル・チョコプラのチャンネルを優先）

### 8.4 採用の確認（全候補に共通）
1. `python -m src.list_uploads <動画IDかチャンネルID> --start … --end …` で、公開時刻とコメントの有効・無効を確認（コメントは取らない）
2. `experiments\fetch_comments.ps1 -Ids …` でコメントを取得
3. `observe --freq 3h --start … --end …` で、評価期間（炎上は基準時刻の前24時間〜後48時間、比較は同じ長さ）に判定できる時間帯があることを確認。0なら不採用として理由を記録

## 9. 本評価の実行（2026-11-10 決定：規則による自動選定）

8章の候補から、基準時刻を掲載時刻つきの外部資料で決められた5つの騒動を `experiments/incidents_main.csv` に固定した（こめお・ヒカル・中町兄妹・りせとルイス・チョコプラ。はんじょうは開始時刻に幅があるため除外）。

```powershell
$env:YOUTUBE_API_KEY = "（手元のキー）"
.venv\Scripts\python.exe -m experiments.prepare_main_eval      # 選定・取得・判定できる時間帯の確認 → data\research\labels.csv
# 比較動画の期間に騒動の報道がないかを確認し、labels.csv の label_source に追記
powershell -ExecutionPolicy Bypass -File experiments\run_main_evaluation.ps1
```

- 選び方の規則は `prepare_main_eval.py` の先頭に書いたとおり（動画の情報と「判定できる時間帯の数」だけを使い、警戒の有無などの結果は見ない）
- 評価期間は全動画120時間（`eval_start_jst`・`eval_end_jst` 列）。この列がないラベルは、従来どおり全履歴で数える
- チャンネルは名前検索（`search:`）で決めるものがあるので、`results\prepare_main_eval.csv` の channel_title が正しいチャンネルかを確認する

### 9.3 3回目の実行と、本評価に進む判断（2026-11-10、検知結果を見る前に決定）
- 3回目の結果：炎上4（こめお・ヒカル・りせとルイス・チョコプラ）・比較5（ヒカル・りせとルイス・チョコプラ・なるにぃ・シバター）
  - シバター：炎上候補（7/21〜7/28 公開の3本、各346〜550件）は判定できる時間帯なし。支援を報告した8/1の動画は候補に出なかった（非公開・削除の可能性）。比較 IZfFxVBd1zk（2026-06-29〜07-04）は採用、期間内の騒動報道なし

- 比較動画の期間に騒動の報道がないことは確認済みで、labels.csv の label_source に記録した
