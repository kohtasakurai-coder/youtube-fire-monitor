# STEP 8：卒業論文の構成案

**題目**：YouTubeコメントの時系列感情分析と異常検知を用いた炎上早期検知システムの開発と評価

この文書は、実装済みのシステムから「事実として書けること」と「実験後に埋めること」を分けて整理したものです。
**【結果待ち】** の箇所は、評価実験（`experiments/compare_methods.py` の `tune` → `test` → `report`）の出力から数値を転記します。数値・引用文献を推測で書かないこと。

## 第1章　序論

### 1.1 研究背景（書く内容）
- 企業の不祥事などをきっかけに、動画のコメント欄で批判が短時間に集中する現象（炎上）がある
- 炎上の発生をできるだけ早く把握できれば、対応を検討する時間が得られる
- 一方、不祥事を報じるニュース動画はもともと否定的なコメントが多く、「話題が否定的であること」と「炎上」を区別する必要がある
- ※ 炎上の社会的影響を述べる場合は、出典のある文献・統計を引用する（数値を推測で書かない）

### 1.2 研究目的
- YouTubeコメントを時系列で分析し、否定的感情の急増とコメント数の異常な増加から炎上の発生を早期に検知するシステムを開発する
- 3種類の異常検知手法を、検知精度・誤警戒・検知までの時間で比較する
- 本研究は未来予測ではなく、発生の早期検知を目的とする（データリークを排除した評価を行う）

## 第3章　提案システム

### 3.1 システム構成（実装済み・事実として書ける）
- Python、Streamlit（Webアプリ）、Janome（形態素解析）、ruptures（PELT）、Plotly（グラフ）
- 処理の流れ：コメント取得（YouTube Data API v3）→ 前処理（日本時間への変換）→ 感情分析 → 1時間ごとの集計 → 手法A・B・C → 警戒レベル → 可視化・評価
- 画面：ホーム、分析ダッシュボード、アルゴリズム比較、データ確認
- 図：`docs/STEP1_設計書.md` 3章のアーキテクチャ図
- データの保存：設計時にはSQLiteも候補としたが、最終実装ではコメントデータをCSVで保存した（Streamlit Community Cloud ではファイルが保持されないため、CSVのアップロード・ダウンロードで受け渡す）
- 完成確認：Windowsの開発環境で画面テストを含む143件のテストが合格。非公開の Streamlit Community Cloud で、架空データの読み込みから検知・比較表の表示まで動作を確認

### 3.2 データ収集
- `commentThreads.list` でトップレベルコメント、`comments.list` で返信を取得（1回最大100件、1クォータ単位）
- 取得項目：コメントID、投稿日時、本文、いいね数、親コメントID、返信かどうか。投稿者名・チャンネルIDは取得しない
- 【結果待ち】対象動画の本数、選定基準、取得期間、取得率（取得件数／総コメント数）

### 3.3 感情分析
- NFKC正規化 → Janome で形態素解析 → 最大4語の連続（最後の語のみ基本形）を辞書と照合
- 否定の扱い：感情語の直後3語以内に「ない・ぬ・ん・ず」（助動詞・形容詞）があれば数えない。「〜しかない」は否定とみなさない
- スコア：M＝数えた感情語の数、m_e＝感情 e の語数として score_e = m_e / M、否定的 ⇔ (anger・fear・sadness の語数)/M ≥ 0.5。M=0 は判定不能（肯定とみなさない）
- 辞書：NRC Emotion Lexicon 日本語版（研究用、再配布不可）、自作簡易辞書（222語、公開デモ用）
- 辞書の使い分け：ローカル研究版は `Japanese-NRC-EmoLex.txt` があればNRCを初期選択（簡易辞書に切替可）。公開デモ版は簡易辞書のみ。感情分析と検知で同じ辞書を使い、結果CSVに辞書名を記録する
- 評価結果は 5.1 節（下記）。判定基準は `コメント判定基準.md`（否定的=1／非否定=0／保留）

### 3.4 時系列の作成
- 1時間ごと（30分・3時間も可）に、コメント数、否定的コメント数、否定的コメント率 N_t、5感情の平均、移動平均を計算
- 0件の時間帯も残し、比率は欠損とする。10件未満は信頼性が低い時間帯として扱う

### 3.5 異常検知手法（すべてオンライン：時刻 t の判定には t までのデータだけを使う）
- 手法A（否定率の上昇）：N̄_t = Σ_{s∈B_t} n_s^neg / Σ_{s∈B_t} n_s（B_t は直前24時間）。n_t ≥ 10、Σn_s ≥ 10、N_t − N̄_t ≥ δ で検知。オプションで二項検定 P(X ≥ n_t^neg | Bin(n_t, N̄_t)) ≤ α
- 手法B（投稿数）：Z_t = (n_t − μ_t)/max(σ_t, 1)、Z_t > 閾値 かつ n_t ≥ 10 で検知
- 手法C（オンラインPELT）：各時刻で、直近72時間のうちコメント10件以上の時間帯の否定率に PELT（rbf）を適用。直近3時間以内の変化点で、変化後−変化前 ≥ 15ポイントなら、その時刻に検知。**変化点の位置と検知できた時刻は区別する**
- 警戒レベル：同じ時間帯に2手法以上が検知＝警戒、直近3時間に検知あり＝注意
- データリーク対策：未来のデータを追加しても過去の判定が変わらないことをテストで確認（`tests/test_anomaly.py`。わざとリークさせると失敗することも確認済み）

## 第4章　評価実験

### 4.1 データセットと正解ラベル
- 炎上の定義、炎上開始時刻の決め方（外部の報道・公式発表の時刻。コメントからは決めない）
- 対象にできる動画の条件：**炎上のきっかけより24時間以上前に公開されていた動画**（各手法は直前24時間と比べるため、公開直後に始まった炎上は設計上判定できない）。選定手順は `docs/本評価_動画選定手順.md`
- フジテレビの会見前後の比較（TeRXuoLAX9o、基準時刻 2025-01-27 16:00 JST）は**予備評価**として別に報告し、会見開始時刻は炎上開始の正解ラベルに使わない
- 【結果待ち】炎上 n 本・非炎上 n 本（うち否定的な話題の非炎上 n 本）、事件数
- 正解ラベルは評価前に固定（SHA-256 を記録：`experiments/protocol/labels_sha256.txt`）

### 4.2 評価方法（実装済み・事実として書ける）
- **本研究で採用する方針（小規模評価）**：閾値は設計書の既定値に固定して調整せず、全動画を1回だけ評価する。集計幅は3時間を主とし、1時間を併記する。集計幅はコメント量（判定できる時間帯の数）だけで本評価の前に決めた。以下の dev/test による調整手順は、動画を十分に集められた場合の方法として実装している
- 事件単位で調整用（dev）と評価用（test）に分割（炎上を含む事件・含まない事件それぞれ40%を dev）
- dev でパラメータを総当たりし、事前に決めた規則（「警戒」の F1 最大 → 100時間あたり誤警戒 → 遅れ中央値）で1つ選択。test は1回だけ評価
- 正解：炎上開始 ≤ 検知時刻 ≤ 開始+48時間。開始前の警報は誤警戒
- 指標：Precision、Recall、F1（動画単位）、誤警戒率（非炎上動画の割合・100時間あたり）、検知の遅れ（検知時刻 − 開始）
- 区間推定：Wilson 95%信頼区間、F1 はブートストラップ。手法間の比較は McNemar 正確検定
- 全期間を使った事後分析（オフライン PELT）は参考値として別に示し、指標には含めない

**結果を読むときの注意（本文に書く）**
- 評価データの94%（184/195）が否定で、非否定は11件しかない。そのため適合率は「否定と予測したものがほぼすべて否定だった」ことを示すが、非否定を誤って否定とする傾向（特異度）はほとんど評価できていない
- 非否定11件のうち10件は、YouTubeテーマソングの1スレッド（同じ親コメントへの返信）から来ている。NRCの誤検知1件もこのスレッド内。テーマソングを除いた183件では、NRCは TP 100・FP 0・FN 82・TN 1（適合率 1.000 [0.963, 1.000]、再現率 0.549 [0.477, 0.620]）で、結論は変わらない
- 再現率の低さの主な原因は判定不能：否定184件のうち、自作辞書では147件、NRCでは66件が辞書に一致する語を含まなかった
- 動画別の再現率（NRC）：スシロー 0.583、0COsmOuLz5A 0.500、1tjzpOjtFcM 0.483、UOJSeEX-WuM 0.552
- 判定者は1名。第2判定者による一致度（Cohen の κ）は未測定（今後の課題）

**辞書の採用理由（本文に書く）**
- 同じ人手ラベル195件で比べると、NRC日本語辞書は判定カバー率 63.6%、否定の再現率 54.3%、F1 0.702 で、比較した2つの辞書の中で最良だった（自作辞書：カバー率 21.5%、再現率 14.1%、F1 0.248）。適合率は両者とも高く差が小さい（1.000 と 0.990）ため、判定できるコメントの多さと再現率を理由に、本研究の分析・検知ではNRC日本語辞書を使う
- 評価の限界：非否定11件のうち10件が同じスレッドに偏っているため、非否定を否定と誤る傾向は十分に評価できていない（上記の注意を参照）

- マネーのクズ特別編では9月16日12:00〜18:00にコメントが急増し注意が出たが、警戒（2手法以上の一致）にはならなかった。騒動の影響の有無は確認できていないため、比較用（非炎上）にも炎上にも分類しない
- どちらも件数の少ない時間帯（13〜20件）での判定を含む

**比較用動画の状況**
- 手元にある3本（LINEヤフー 1tjzpOjtFcM：157件、au UOJSeEX-WuM：219件、CWz7Vi1xe0M：36件）は、1時間・3時間集計のどちらでも全期間で判定できた時間帯が0。「警戒なし」を観測できないため採用しない
- マネーのクズ特別編は上記の理由で比較用にしない。比較用には、騒動の影響が及びにくい別チャンネルの動画を探す（`docs/本評価_動画選定手順.md`）

## 第6章　考察（観点の候補）
- 否定的な話題のニュース動画で誤警戒が出たか／出なかったか（動画自身の過去と比べる設計の効果）
- 件数の少ない時間帯の偶然の上振れと二項検定の効果（架空データでは誤警戒が減った。実データでどうか）
- 手法C は誤警戒が少ない一方、検知が数時間遅れる傾向（PELT が変化後に最低2点を必要とするため）
- 感情分析のカバー率と誤判定（皮肉・否定・文脈）が検知に与えた影響。NRCでも否定的コメントの約46%を見逃す（5.1節）ため、手法A・Cの否定率は実際より低く出る。否定率の「水準」ではなく「動画自身の過去からの変化」を見る設計は、この過小評価が時間的に一定なら影響を受けにくい
- 小標本のため信頼区間が広いこと
