## 第1章　序論

### 1.1 研究背景（書く内容）
- 企業の不祥事などをきっかけに、動画のコメント欄で批判が短時間に集中する現象（炎上）がある
- 炎上の発生をできるだけ早く把握できれば、対応を検討する時間が得られる
- 一方、不祥事を報じるニュース動画はもともと否定的なコメントが多く、「話題が否定的であること」と「炎上」を区別する必要がある
- ※ 炎上の社会的影響を述べる場合は、出典のある文献・統計を引用する（数値を推測で書かない）

### 1.2 研究目的
- YouTubeコメントを時系列で分析し、否定的感情の急増とコメント数の異常な増加から炎上の発生を早期に検知するシステムを開発する
- 3種類の異常検知手法を、検知精度・誤警戒・検知までの時間で比較する
- 本研究は未来予測ではなく、発生の早期検知を目的とする（データリークを排除した評価を行う）

## 第3章　提案システム

### 3.1 システム構成（実装済み・事実として書ける）
- Python、Streamlit（Webアプリ）、Janome（形態素解析）、ruptures（PELT）、Plotly（グラフ）
- 処理の流れ：コメント取得（YouTube Data API v3）→ 前処理（日本時間への変換）→ 感情分析 → 1時間ごとの集計 → 手法A・B・C → 警戒レベル → 可視化・評価
- 画面：ホーム、分析ダッシュボード、アルゴリズム比較、データ確認
- 図：`docs/STEP1_設計書.md` 3章のアーキテクチャ図

### 3.2 データ収集
- `commentThreads.list` でトップレベルコメント、`comments.list` で返信を取得（1回最大100件、1クォータ単位）
- 取得項目：コメントID、投稿日時、本文、いいね数、親コメントID、返信かどうか。投稿者名・チャンネルIDは取得しない
- 【結果待ち】対象動画の本数、選定基準、取得期間、取得率（取得件数／総コメント数）

### 3.3 感情分析
- NFKC正規化 → Janome で形態素解析 → 最大4語の連続（最後の語のみ基本形）を辞書と照合
- 否定の扱い：感情語の直後3語以内に「ない・ぬ・ん・ず」（助動詞・形容詞）があれば数えない。「〜しかない」は否定とみなさない
- スコア：M＝数えた感情語の数、m_e＝感情 e の語数として score_e = m_e / M、否定的 ⇔ (anger・fear・sadness の語数)/M ≥ 0.5。M=0 は判定不能（肯定とみなさない）
- 辞書：NRC Emotion Lexicon 日本語版（研究用、再配布不可）、自作簡易辞書（222語、公開デモ用）
- 【結果待ち】人手の正解200件での適合率・再現率・カバー率（`sentiment` コマンド）。予備評価20件の値は本文ではなく付録扱いにする

### 3.4 時系列の作成
- 1時間ごと（30分・3時間も可）に、コメント数、否定的コメント数、否定的コメント率 N_t、5感情の平均、移動平均を計算
- 0件の時間帯も残し、比率は欠損とする。10件未満は信頼性が低い時間帯として扱う

### 3.5 異常検知手法（すべてオンライン：時刻 t の判定には t までのデータだけを使う）
- 手法A（否定率の上昇）：N̄_t = Σ_{s∈B_t} n_s^neg / Σ_{s∈B_t} n_s（B_t は直前24時間）。n_t ≥ 10、Σn_s ≥ 10、N_t − N̄_t ≥ δ で検知。オプションで二項検定 P(X ≥ n_t^neg | Bin(n_t, N̄_t)) ≤ α
- 手法B（投稿数）：Z_t = (n_t − μ_t)/max(σ_t, 1)、Z_t > 閾値 かつ n_t ≥ 10 で検知
- 手法C（オンラインPELT）：各時刻で、直近72時間のうちコメント10件以上の時間帯の否定率に PELT（rbf）を適用。直近3時間以内の変化点で、変化後−変化前 ≥ 15ポイントなら、その時刻に検知。**変化点の位置と検知できた時刻は区別する**
- 警戒レベル：同じ時間帯に2手法以上が検知＝警戒、直近3時間に検知あり＝注意
- データリーク対策：未来のデータを追加しても過去の判定が変わらないことをテストで確認（`tests/test_anomaly.py`。わざとリークさせると失敗することも確認済み）

## 第4章　評価実験

### 4.1 データセットと正解ラベル
- 炎上の定義、炎上開始時刻の決め方（外部の報道・公式発表の時刻。コメントからは決めない）
- 【結果待ち】炎上 n 本・非炎上 n 本（うち否定的な話題の非炎上 n 本）、事件数
- 正解ラベルは評価前に固定（SHA-256 を記録：`experiments/protocol/labels_sha256.txt`）

### 4.2 評価方法（実装済み・事実として書ける）
- 事件単位で調整用（dev）と評価用（test）に分割（炎上を含む事件・含まない事件それぞれ40%を dev）
- dev でパラメータを総当たりし、事前に決めた規則（「警戒」の F1 最大 → 100時間あたり誤警戒 → 遅れ中央値）で1つ選択。test は1回だけ評価
- 正解：炎上開始 ≤ 検知時刻 ≤ 開始+48時間。開始前の警報は誤警戒
- 指標：Precision、Recall、F1（動画単位）、誤警戒率（非炎上動画の割合・100時間あたり）、検知の遅れ（検知時刻 − 開始）
- 区間推定：Wilson 95%信頼区間、F1 はブートストラップ。手法間の比較は McNemar 正確検定
- 全期間を使った事後分析（オフライン PELT）は参考値として別に示し、指標には含めない

## 第6章　考察（観点の候補）
- 否定的な話題のニュース動画で誤警戒が出たか／出なかったか（動画自身の過去と比べる設計の効果）
- 件数の少ない時間帯の偶然の上振れと二項検定の効果（架空データでは誤警戒が減った。実データでどうか）
- 手法C は誤警戒が少ない一方、検知が数時間遅れる傾向（PELT が変化後に最低2点を必要とするため）
- 感情分析のカバー率と誤判定（皮肉・否定・文脈）が検知に与えた影響
- 小標本のため信頼区間が広いこと

## 研究上の制約（本文に必ず書く）
- APIで取得できるのは現在残っているコメントのみ（削除・非表示は含まない）。編集されたコメントは編集後の本文
- 取得上限に達した動画は古いコメントが欠ける
- 辞書ベースの感情分析の限界（皮肉、文脈、機械翻訳辞書の誤訳）
- 炎上開始時刻の定義の不確かさ
- 警戒レベルは研究上の暫定基準
